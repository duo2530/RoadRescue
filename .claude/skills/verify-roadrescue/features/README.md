# 道路救援验证地图

这个目录是「道路救援服务平台」用户可见行为的验证依据。驱动前先读本页，再按对应功能文件的步骤操作。

## 基线前提

- `doctor.sh` 全部通过：六个 `roadrescue-*` 容器 healthy，网关 8600 可用，三个前端在 `localhost:9527/9090/9091` 返回 200。
- 演示数据已导入（`backend/sql/test-data.sql`）：乘客 ID 1、司机 ID 1，司机认证通过且已开启接单。
- 演示登录开关打开：Nacos `web-customer-dev.yaml`、`web-driver-dev.yaml` 里 `roadrescue.demo-login.enabled: true`。
- 管理端账号 `admin` / `111111`。
- 不要驱动不是本次验证启动的实例以外的东西：本机还有其他项目的容器（`wm-*`、`tjxt-*` 等），不要碰。

## 驱动约定

- 管理端优先用角色和名称（`menuitem "救援工单"`），它的可访问性名称完整。
- 乘客端、司机端是 uni-app H5，元素多为无角色的 `view`。用 `eval 'document.body.innerText'` 读文字断言；点击前先确认目标没有被其他元素覆盖，匹配到文字不等于点中了按钮。
- 后端行为优先用网关接口验证，再用 UI 做补充。
- 每个功能从基线状态开始，除非功能文件另有前提。
- 变更之后用数据库或第二个接口回读，不只看页面提示。

## 证明与跳过的报告方式

- UI 证明包含截图和文字快照，截图里能看到“道路救援”标识。
- 接口证明包含请求、响应体和 HTTP 状态。
- 写入类证明包含一次只读回读（SQL 或另一个接口）。
- 每份产物记录功能 ID 和使用的入口。
- 到达不了的路径，写出尝试过的命令和没满足的前提；不要用别的入口顶替后报告为已验证。
